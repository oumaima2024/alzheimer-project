# ADNI RQ3 Audit Report

Date: 2026-10-27

## Scope

The project was audited against the requirements in `README.md`: define an MCI baseline cohort, label MCI-to-AD conversion from follow-up information, prevent participant/measurement leakage, compare Logistic Regression, Random Forest, MLP, GRU, and LSTM, run tests and real experiments, and package reproducible artifacts.

## Data actually used

The archive contains:copy /Y "FULL_PATH_TO_YOUR_CORRECTED_FILE.csv" "outputs\ADNI_files_summary.csv"



- `data/raw/CDR_27Oct2026.csv`: 15,137 CDR rows, 4,389 participants.

- `data/raw/ITEM.csv`: 5,341 source rows before deterministic participant-visit de-duplication; 5,285 rows after de-duplication, 755 participants.

The following declared inputs were not present:

- `DXSUM_PDXCONV_ADNIALL.csv` — the pipeline therefore used CDR-based labels, not DXSUM diagnosis labels.

- `ADNIMERGE.csv` — age, education, sex, and APOE4 were unavailable.

The CDR fallback retained 1,346 participants after baseline CDR=0.5, at least two visits, and at least six months of follow-up: 490 converters and 856 stable MCI participants. The participant-level split was train=941, validation=135, test=270, with a 0.36 converter fraction in each split.

The real export did not provide usable baseline values for `MMSE_TOTAL`, `ADAS_TOTAL`, `AVLT_T5`, `AVLT_DELAY`, `BOSTON_NAMING`, or `TMT_B` after joining ITEM to CDR by `(RID, VISCODE_NORM)`. Those features were excluded consistently by the corrected training schema because they were entirely unobserved in the training split. The real experiments therefore used the eight observed CDR features. This is not a fabricated imputation result; the missingness was measured directly.

## Corrections made

1. Baseline cohort selection no longer uses `groupby.first()`, which can combine the first non-null values from different visits. It now selects the actual first sorted visit row.

1. The configured minimum follow-up duration is now enforced for both CDR and DXSUM label paths.

1. Labels now retain `CONVERSION_MONTH` and `FOLLOWUP_MONTHS` metadata.

1. Longitudinal sequences exclude the conversion visit and all later visits for converters. Stable participants retain their observed follow-up visits.

1. ITEM duplicate participant-visit rows are deterministically de-duplicated before merging.

1. The preprocessing pipeline now drops all-missing training columns once and reuses the same observed feature schema for tabular and sequence models, avoiding a real-data shape mismatch.

1. Running GRU and LSTM sequentially now preserves both model records in `longitudinal_results.json` and `longitudinal_metrics.csv` instead of overwriting the previous model.

1. Added regression tests for future-value backfill, minimum follow-up filtering, and post-conversion sequence exclusion.

- Results are from one fixed participant split, not repeated cross-validation or an external test cohort.

- The comparison script currently produces metric/summary figures; it does not redraw a combined ROC curve from saved probability arrays because probability arrays are not persisted.

## Reproduction

From `adni_rq3/` after installing `requirements.txt`:

```bash
pytest -q
python scripts/train_baseline.py --config config.yaml --no-shap
python scripts/train_longitudinal.py --config config.yaml --model-type GRU
python scripts/train_longitudinal.py --config config.yaml --model-type LSTM
python scripts/compare_models.py --results-dir results
```

Do not interpret the reported metrics as diagnosis performance without first supplying the missing DXSUM/ADNIMERGE/neuropsych inputs and deciding whether CDR-based labels are acceptable for the study protocol.
